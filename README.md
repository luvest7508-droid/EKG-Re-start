# ECG Re:Start — THE ECG ESCAPE ROOM

응급실 간호사를 위한 심전도 판독 방탈출 웹 게임 (MVP)

- 교육생: 개인 스마트폰으로 QR 코드 또는 URL에 접속해 팀 단위로 참여
- 강사: 강의실 PC 대시보드를 프로젝터로 송출해 진행 상황 관리
- 설치할 프로그램 없음 (HTML · CSS · JavaScript)

---

## 1. 폴더 구조

```
ecg-restart/

├─ content/questions.js    ★ 교육 콘텐츠 (문제·정답·해설·암호) — 화면 코드와 분리
├─ images/                 ECG 이미지 보관 폴더 (직접 추가)
├─ js/
│  ├─ config.js            ★ 실행 모드(DEMO/Firebase)·점수 규칙 설정
│  ├─ sync.js              데이터 동기화 계층 (DemoAdapter / FirebaseAdapter)
│  ├─ engine.js            게임 규칙 (점수·진행·순위)
│  ├─ player.js            교육생 화면
│  ├─ host.js              강사용 대시보드
│  ├─ editor.js            문제 관리
│  ├─ app.js               라우팅
│  └─ vendor/qrcode.js     QR 코드 생성 (MIT)

```

접속 주소

| 주소 | 화면 |
|---|---|
| `https://(배포주소)/` | 시작 화면 (교육생 / 강사 선택) |
| `https://(배포주소)/?role=host` | 강사용 대시보드 |
| `https://(배포주소)/?role=player&s=1234` | 교육생 화면 (QR 코드가 이 주소를 담습니다) |

## 2. DEMO MODE로 바로 시연하기 (백엔드 불필요)

`js/config.js`의 `MODE: 'demo'`(기본값) 상태로 실행합니다.

1. 폴더에서 로컬 서버 실행: `python3 -m http.server 8000` → 브라우저에서 `http://localhost:8000/?role=host`
   (또는 VS Code의 Live Server, 아래 3번의 GitHub Pages·Netlify 배포 주소)
2. **세션 생성** → 왼쪽 패널의 **교육생 화면 새 탭으로 열기** → 팀명 입력
3. 탭을 여러 개 열면 팀이 여러 개 생깁니다. **리허설용 가상 팀 3개 추가**를 누르면 가상 팀이 자동으로 문제를 풉니다.
4. 강사 탭에서 **게임 시작** → 교육생 탭에서 진행

> ⚠ DEMO MODE는 **같은 브라우저의 탭끼리만** 데이터가 공유됩니다(localStorage + BroadcastChannel). 다른 사람의 스마트폰과는 연결되지 않습니다. 실제 수업은 4번(Firebase)을 설정하세요.

## 3. 웹에 배포하기 (QR 접속용 주소 만들기)

배포 후 강사 화면의 QR 코드는 자동으로 배포 주소를 사용합니다. **HTTPS 주소**여야 스마트폰에서 문제없이 열립니다.

### 방법 A. Netlify Drop (가장 쉬움, 무료)
1. https://app.netlify.com/drop 접속 (무료 회원가입)
2. `ecg-restart` 폴더를 통째로 끌어다 놓기
3. 생성된 `https://xxxx.netlify.app` 주소 사용 (사이트 설정에서 이름 변경 가능)
4. 수정 후에는 Deploys 탭에서 폴더를 다시 끌어다 놓으면 갱신됩니다.

### 방법 B. GitHub Pages (무료)
1. GitHub에서 새 저장소 생성 (예: `ecg-restart`, Public)
2. **Add file → Upload files**로 폴더 안의 파일·폴더를 모두 업로드 → Commit
3. **Settings → Pages → Source: Deploy from a branch → main / (root)** → Save
4. 1~2분 후 `https://(아이디).github.io/ecg-restart/` 로 접속

### 방법 C. Firebase Hosting
Firebase를 이미 쓰는 경우: `npm i -g firebase-tools` → `firebase login` → 폴더에서 `firebase init hosting`(public 디렉터리: `.`) → `firebase deploy`

## 4. Firebase 설정 (여러 스마트폰 실시간 연결)

무료 Spark 요금제로 충분합니다(동시 접속 100명, 30명 수업 기준 여유).

1. https://console.firebase.google.com → **프로젝트 추가** (Google 애널리틱스는 꺼도 됨)
2. **빌드 → Authentication → 시작하기 → 로그인 방법 → 익명(Anonymous) → 사용 설정**
3. **빌드 → Realtime Database → 데이터베이스 만들기**
   - 위치: `asia-southeast1 (싱가포르)` 권장
   - 잠금 모드로 시작 → **규칙** 탭에 `database.rules.json` 내용을 붙여넣고 **게시**
4. **프로젝트 설정(톱니바퀴) → 일반 → 내 앱 → 웹(</>) 앱 추가** → 표시되는 `firebaseConfig` 값을 복사
5. `js/config.js` 수정
   ```js
   MODE: 'firebase',
   FIREBASE: {
     apiKey: 'AIza...',
     authDomain: 'ecg-restart.firebaseapp.com',
     databaseURL: 'https://ecg-restart-default-rtdb.asia-southeast1.firebasedatabase.app',
     projectId: 'ecg-restart',
     storageBucket: '...', messagingSenderId: '...', appId: '...'
   }
   ```
6. 다시 배포 → 강사 화면 상단 배지가 **LIVE · Firebase**로 바뀌면 성공
   (값이 비었거나 연결에 실패하면 자동으로 DEMO MODE로 실행되고 안내 메시지가 뜹니다)

**보안 규칙이 하는 일**
- 세션을 만든 강사 기기(익명 uid)만 게임 상태·문제를 변경하고 모든 팀 데이터를 읽을 수 있습니다.
- 교육생은 **자기 팀 데이터만** 읽고 쓸 수 있습니다 → 다른 팀의 정답·점수 조회 불가.
- 강사는 **세션을 만든 같은 PC·브라우저**에서 진행하세요(다른 기기에서는 강사 권한이 없습니다).
- 수업 후 Realtime Database 콘솔에서 `sessions` 노드를 삭제하면 기록이 정리됩니다. 팀명에는 개인정보(실명·사번)를 쓰지 않도록 안내하세요.

## 5. 수업 당일 진행 순서

1. 강의실 PC에서 `?role=host` 접속 → 제한시간 입력(기본 20분) → **세션 생성**
2. 프로젝터에 QR 코드·세션 코드 표시 → 교육생 팀별 접속, 팀명 입력 (팀당 스마트폰 1대 권장)
3. 입장 팀 수 확인 후 **게임 시작** — 필요 시 **일시정지 / ±1분 / 게임 종료**
4. 진행 중: **진행 현황**(Room별 팀 분포, 순위), **미션 정답률**(1차 정답률 50% 미만 문항 강조)
   - 경쟁이 과열되면 **프로젝터에서 점수 숨기기** 체크
5. 종료 후: **정답·해설** 탭에서 문항별 선택 분포를 보여준 뒤 **정답·해설 공개**(키보드 ← → 이동, Space 공개)
6. **결과 발표** → 시상대 화면

## 6. 게임 규칙과 점수 체계

| 항목 | 기본값 | 설정 위치 |
|---|---|---|
| 1차 시도 정답 | 배점의 100% | `config.js > SCORING.firstTry` |
| 2차 시도 정답 | 50% | `secondTry` |
| 3차 이후 정답 | 20% | `laterTry` |
| 힌트 사용 | 해당 문항 배점의 −30% | `hintRate` |
| **위험 판단** 선택 | −50점 | `dangerPenalty` |
| 잠금장치 암호 오입력 | −10점 | `passwordPenalty` |
| 제한시간 내 전체 완료 | 최대 +300점 (남은 시간 비율) | `timeBonusMax` |

- 배점은 난이도·임상 판단 비중에 따라 문항별로 다르게 설정합니다(기본: 판독 100–150, 처치 판단 200, FINAL 200–250).
- **임상 판단 반영**: 실제 환자에게 위해가 될 수 있는 선택지(예: 맥박 있는 VT에 비동기 제세동, PEA에 제세동)는 `danger: true`로 표시되어 오답에 더해 감점되고, 강사 화면에서 "위험 판단" 횟수로 따로 집계됩니다.
- 오답을 고르면 해당 선택지가 왜 틀렸는지 피드백을 주고 다시 도전하게 합니다. 정답 시 전체 해설과 **암호 조각**을 줍니다.
- 한 Room의 미션을 모두 풀면 모은 조각(순서가 섞여 표시됨)을 단서에 맞게 배열해 암호를 입력해야 다음 Room이 열립니다.
- 순위: 총점 → 동점이면 먼저 완료한 팀.

## 7. 문제 수정 (콘텐츠 관리)

### 방법 1. 강사 화면에서 편집 (권장)
1. 강사 화면 → **문제 관리** (세션을 만들기 전에도 열 수 있음)
2. 문제 제목·내용·ECG 이미지·선택지·정답·해설·난이도·배점·암호 조각·Room 암호 수정 → 자동 저장
3. 수정본은 **이 브라우저에 저장**되며 **다음 세션 생성 시** 반영됩니다. 진행 중 세션에는 **현재 세션에 적용**으로 반영할 수 있습니다(문항 순서·개수 변경은 비권장).
4. **영구 반영**: **questions.js 내보내기** → 받은 파일로 `content/questions.js`를 교체 → 재배포
   (다른 PC에서도 같은 문제를 쓰려면 이 방법을 사용하세요. JSON 내보내기·가져오기로 백업도 가능)

### 방법 2. `content/questions.js` 직접 편집
파일 상단에 필드 설명이 있습니다. 화면 코드는 건드릴 필요가 없습니다.

### ECG 이미지 등록
- **이 MVP에는 ECG 이미지가 포함되어 있지 않습니다.** 모든 문항은 판독 소견을 텍스트로 제시하며, 이미지 자리에 "ECG 이미지 미등록"이 표시됩니다.
- ROOM 03(12유도)은 실제 12유도 ECG 이미지를 등록해야 교육 목표에 맞습니다.
- 권장 방식: 이미지 파일을 `images/` 폴더에 넣고 문제 관리의 **ECG 이미지 URL**에 `images/파일명.png` 입력 → 재배포
- 소수의 이미지는 **이미지 파일 업로드**도 가능(자동 압축, 해당 브라우저 수정본에 저장)
- 원내 교육자료 등 **출처와 사용 허락이 확인된 실제 ECG**만 사용하고, **이미지 출처·라이선스** 칸에 기록하세요. 이미지 속 환자 식별정보는 반드시 가리세요.
- 이미지를 바꾸면 판독 소견(문제 내용)·정답·해설이 그 이미지와 일치하는지 다시 확인하세요.

## 8. 샘플 콘텐츠 안내 (반드시 검토)

- 4개 Room 17문항은 **교과서적 진단 기준과 AHA ACLS 알고리즘**을 바탕으로 작성한 샘플입니다. 환자 상황은 교육용 가상 사례이며 실제 진단 사례가 아닙니다.
- 약물 용량·재관류 목표 시간 등은 최신 가이드라인과 **기관 프로토콜**에 맞게 교육 전 검토하세요.
- 각 문항의 `reference` 칸에 근거를 표시했습니다.

## 9. 현재 한계와 확장 계획

| 현재(MVP) | 확장 방향 |
|---|---|
| 정답 데이터가 브라우저로 전송됨 (개발자 도구로 확인 가능) | Cloud Functions 서버 채점 |
| 팀당 기기 1대 기준 | 같은 팀 여러 기기 동시 접속 |
| 객관식 + 암호 입력 | 이미지 영역 탭(ST 상승 유도 찾기), 순서 배열형 |
| 문제 수정본은 브라우저 단위 저장 | 강사 계정 로그인 + 문제 은행 DB 저장 |
| 결과는 화면으로만 확인 | 결과 CSV 내보내기, 사전·사후 평가 연동 |
